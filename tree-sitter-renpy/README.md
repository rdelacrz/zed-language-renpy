# tree-sitter-renpy

A [tree-sitter](https://tree-sitter.github.io/tree-sitter/) grammar for the
[Ren'Py](https://www.renpy.org/) visual-novel scripting language.

This grammar is the **syntax half** of the Zed Ren'Py extension. Zed requires every language to
reference a tree-sitter grammar; it uses the parse tree (together with the `.scm` query files shipped
in the extension's `languages/renpy/` directory) for **syntax highlighting, bracket matching,
indentation, code folding, and the outline**. Language *intelligence* (completion, hover, diagnostics,
etc.) is provided separately by the LSP server in `../server`.

```
Zed editor ──parses with──▶ tree-sitter-renpy  ──tree──▶ highlights/outline/indents (via .scm queries)
```

## How Zed consumes it
The extension's `extension.toml` references this grammar by git repository + commit:

```toml
[grammars.renpy]
repository = "file:///…/tree-sitter-renpy"   # or a GitHub URL when published
commit = "<sha>"
```

The `*.scm` query files (`highlights.scm`, `outline.scm`, `injections.scm`, …) that map this grammar's
nodes to editor features live in the **extension**, not here.

## Content / layout

```
tree-sitter-renpy/
├── grammar.js          # the grammar definition (rules) — the source of truth
├── package.json        # declares tree-sitter-cli (used via `npx tree-sitter …`)
├── tree-sitter.json    # tree-sitter package metadata
├── test/corpus/*.txt   # parser tests (input + expected S-expression tree)
└── src/                # GENERATED by `tree-sitter generate` — do not edit by hand
    ├── parser.c        #   the generated parser
    ├── grammar.json    #   serialized grammar
    ├── node-types.json #   node/field type catalog
    └── tree_sitter/    #   generated headers
```

## Grammar design (v1)
Two-tier structure (see `grammar.js`):
- **Top level** — full statement recognition: `label`, `menu`/`menu_choice`, `screen`, `define`,
  `default`, `transform`, `style`, `image`, `init`, `python`, `if`/`elif`/`else`, `while`, `for`,
  `jump`, `call`, `show`, `scene`, `hide`, `with`, `use`, `return`, `play`/`stop`/`queue`, `say`
  statements, etc. Definition headers expose the defined name as a field (e.g. `label name:`).
- **Block bodies** — currently **opaque** `body_line` nodes. `python:` / `init python:` blocks expose
  a block node so the extension can inject the Python grammar.
- **Strings** expose `interpolation` (`[expr]`), `text_tag` (`{tag}`), and `escape_sequence` children.

### ⚠️ v1 tradeoff: no external scanner
An external INDENT/DEDENT scanner was prototyped but **removed for v1** because it could infinite-loop
on the Python-style off-side rule. Consequence: statements *inside* indented blocks are not
individually parsed (they are `body_line` nodes), so in-block keyword highlighting is limited.
Top-level statements, plus strings/comments everywhere, highlight correctly. A v2 stack-based scanner
(following the `tree-sitter-python` pattern, with EOF handling + zero-width-emission guards) is the
upgrade path for precise nested highlighting.

The full named-node + field contract (what the `.scm` queries can target) is documented in
`../tasks/orchestrator/renpy-zed-extension/implementer-grammar-output.md`.

## Build & test

```bash
cd tree-sitter-renpy
npx tree-sitter generate      # regenerate src/ from grammar.js
npx tree-sitter test          # run test/corpus cases (18/18 passing)
npx tree-sitter parse FILE.rpy
```

> ⚠️ **Never** run `tree-sitter parse --debug-graph` here — it produced a ~50 GB `log.html` and filled
> the disk. `log.html`/`*.log` are git-ignored as a guard. Wrap long parses with `timeout`.
